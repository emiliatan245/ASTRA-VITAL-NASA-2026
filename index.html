Model card — critical limitations

Training values and labels are invented for software demonstration. This model is not trained on NASA or clinical sensor records, cannot validate real sensor quality, and must never be used to assess an actual astronaut or patient. A real mission model would require ethically approved representative data, expert-defined endpoints, external validation, uncertainty analysis, bias testing, human-factors review and flight-medical governance.

THE CHALLENGE

The environment changes.
So can the human body.

Long-duration missions expose crew members to radiation, isolation and confinement, altered gravity and a closed environment. ASTRA-VITAL combines crew-entered observations, measurement-quality checks, mission context and research references to support structured review—not diagnosis.

INTERPRETATION BOUNDARY

What this study cannot tell us

  • It does not provide a continuous heart-rate or sleep stream.
  • It describes a short Inspiration4 mission, not a long-duration mission.
  • Biomarker measurements are not interchangeable with clinical diagnoses.
  • Pre/post-flight associations do not prove that spaceflight caused every observed change.

Import an OSDR CSV / TSV file

BROWSER-ONLY PROCESSING

Download a transformed or processed data file from the NASA OSDR study's Files section, then select it here. The selected file is parsed in your browser; ASTRA-VITAL does not upload it to a server.

How to get a file
  1. Open OSD-575 in NASA OSDR and inspect the Files section.
  2. Read the file descriptions and data dictionary; distinguish sample metadata from assay-result data.
  3. Download an appropriate public processed CSV/TSV file. If OSDR provides a ZIP archive, use Windows Extract All first, then select the CSV/TSV inside it.
  4. If a file contains only metadata, analyse it only as metadata—do not describe it as biomarker measurements.
  5. Confirm that the source is included in the selected 2026 challenge's Resources tab before claiming Global Award data eligibility.
